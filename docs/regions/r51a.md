# Region r51a: the display list (`display_list`) — what other regions need to know

Region r51a ports LibWeb's display list — AccumulatedVisualContext, BorderRadiiData, BordersData,
DisplayList (with DisplayListPlayer's command loop), DisplayListCommand, DisplayListRecorder,
ExternalContentSource, GradientData, PaintStyle, ScrollFrame, ScrollState, ShouldAntiAlias — and
replaces DisplayListPlayerSkia with **DisplayListPlayerCpu**, a CPU player over the `raster`
module (DESIGN.md §7.3). Each fragment's header describes it; `docs/namemap.tsv` lists every name.
The stub fragment `stub_r51a_display_list.lucb` and the generated
`types_display_list_player_skia.lucb` are gone.

## The CPU player

DisplayListPlayerCpu implements the 32 virtuals in DisplayListPlayerSkia.cpp's order with the
same decisions, each Skia call replaced by a CpuCanvas call:

- **Canvas** (`cpu_canvas`): layers (saveLayer with opacity, blend mode, luminance color filter,
  blur, image filter, plus-darker by hand, backdrop filters), states (affine transform; clip as
  device bounds plus an anti-aliased coverage mask when it is not a whole-pixel rectangle; clip
  differences), `quickReject` with Skia's one-pixel outset.
- **Gradients** (`cpu_gradient`, `cpu_color_space`): linear, radial, two-point conical and sweep
  shaders with SkGradientBaseShader's stop normalization, tile modes, degenerate cases,
  premultiplied or unpremultiplied interpolation in sRGB, sRGB-linear, Lab, OkLab, Display P3,
  A98, ProPhoto, Rec2020, HSL, HWB, LCH and OkLCH with the four hue methods. No dithering.
- **Blur** (`cpu_blur`): three box blurs (the SVG window sizes); box shadows blur the shape's
  coverage with the mask filter's sigma mapped by the transform.
- **Surfaces**: the player draws on a canvas per PaintingSurface, made from
  `painting_surface_read_into_bitmap` and written back with `write_from_bitmap` in `flush`
  (only Ladybird's PaintingSurface API is used). Pattern tiles get a surface of their own
  (`painting_surface_create_with_size`) whose canvas starts transparent.
- **Images**: `immutable_bitmap_bitmap` and the Bitmap's scanlines, converted to premultiplied
  RGBA (BGRA/RGBA, x formats opaque).

### Seams to other regions

Two functions in `display_list_player_cpu.lucb` trap with `unported: seam …` until their owner
fills them in (Ladybird has no API for either: the Skia player reaches into PathImplSkia and
FilterImpl through SkiaUtils):

| Seam | Owner | What it must do |
| --- | --- | --- |
| `to_raster_path(path) -> CpuPath?` | r10 (gfx.Path, PathImpl) | the Skia glue `to_skia_path`: the path's contours as a `raster.Path` with its fill type |
| `apply_gfx_filter(filter, pixmap)` | r10 (gfx.Filter, FilterImpl) | `to_skia_image_filter` applied to a pixmap in place |

Glyph runs are drawn from `Path::glyph_run`'s outlines (`text_blob_path`: web_fonts' stubs, then
`to_raster_path`). The text blob's scale lives in r09's CachedTextBlob; until the player can read
it, the outlines are drawn at scale 1, the test runner's only scale (FIXME in the code).

Text, paths, clip paths and filters draw once r09/r10 and these seams exist; everything else
draws today.

### Deviations from the Skia player

- Transforms are 2D: `apply_transform` uses the affine part of the 4x4 matrix (rows/columns 0,
  1, 3); a perspective row is dropped (FIXME in the code).
- Anti-aliased edges come from the raster module's 4x4 supersampling where Skia uses analytic
  coverage: edge pixels of rounded rects, ellipses and lines differ by up to ~48 levels; interiors
  match exactly. Rounded-rect corners are cubic arcs (Skia: conics).
- Gradients are not dithered; the mipmapped scaling mode samples bilinearly.
- The image filter of a layer is applied before its blur and luminance filter.

## Tests

`./test.sh` runs `luce-base test src/luce_browser_render/display_list --native` (70 tests).

- **The CPU player against Skia** (`tests_cpu_player`, data in `tests_skia_reference_data`): 23
  scenes (rects, rounded rects and clips, fractional clips under a scale, opacity and multiply
  layers, translate, rotation, radial/conic/linear gradients, outer and inner box shadows,
  ellipses, rects, solid/dotted/dashed lines) compared with the pixels DisplayListPlayerSkia
  renders for the same display list, under Ladybird's fuzzy rule. Gradients, shadows, layers and
  clips under transforms are within 1–2 levels; only anti-aliased edges differ more.
- **Ported logic, pinned to the donor** (`tests_display_list`): tree building, dumps, hit testing,
  the command loop's exact virtual-call sequence (with a recording player; also culled), command
  dumps and bounds, the recorder's nesting, capture/replay and masks, spread adjustments and
  `CornerRadii::contains`. The expected values were printed by the donor's own C++ compiled
  locally.
- `tests_cpu_canvas`, `tests_cpu_gradient`, `tests_scroll_and_paint_style`: the canvas, blur,
  gradient math and color spaces (against CSS Color 4's values), scroll state, paint styles,
  external content, initial values.

### Gates

Regions r08 and r10 are ported in parallel; tests that reach their stubs return early while
`gfx_geometry_is_ported` / `gfx_paint_is_ported` (`tests_support.lucb`) are false. **Set both to
true after merging r08 and r10.** Every gated test (7 of them, including the linear-gradient and
dotted/dashed-line scenes and the donor's full recorded display list) was run locally against
scratch stand-ins of the gfx functions (never committed) and passed.
